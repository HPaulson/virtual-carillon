# Audio and Content Provenance

The built-in library distinguishes generated instruments, traditional event data, public-domain compositions, and user recordings. A traditional label identifies the source of the pattern or melody; it does not claim that a procedural render is an archival recording.

## Built-in hymn content

The built-in catalog contains source-backed public-domain melodies, not LLM-invented note sequences or commercial recordings. Each hymn owns human-editable structured notation, source URL/provenance, and a separate carillon arrangement plan. The structured notation is serialized to derived ABC and parsed into the runtime melody; Gregorian migrations preserve the normalized pitch, duration, free-rhythm, mode, and phrase data used by the former GABC importer. The renderer turns that melody into an arrangement with phrase-aware chords, bass, inner voices, passing tones, octave doubling, and long natural bell tails.

When a user imports audio, the library stores the user-supplied license, attribution, source URL, and local file reference in `data/assets/index.json` (or `.data/assets/index.json` for native installs).

## Liturgical taxonomy

Every hymn exposes a `liturgicalTags` object made from stable IDs. The fields have distinct meanings:

- `seasons` are broad periods such as `advent`, `lent`, `easter`, and `ordinary-time`.
- `feasts` are named calendar celebrations or genuinely proper observances, such as `assumption-of-mary`, `corpus-christi`, or `good-friday`. Themes such as “passion” and seasons such as Advent are categories/seasons, not feast IDs.
- `categories` are reusable subject or use affinities, such as `marian`, `eucharistic`, `cross-passion`, `resurrection`, `praise`, or `saints`.
- `offices`/`canonicalHours` are reserved for an actual Liturgy-of-the-Hours or antiphon tradition. The supported office categories are Matins, Lauds, Daytime, Vespers, and Compline. They are not synonyms for a feast or a convenient time of day. Most ordinary hymn tunes therefore have no office tag. Every built-in canonical-hour tag must be supported by a cited Ordo, breviary, or actual Office resource; the audit and rite/version scope are recorded in [Office sources](office-sources.md).
- `solemnities` and `memorials` describe the rank of a LitCal celebration. They are useful on calendar events, but are not intrinsic hymn properties and are not used to select hymns.

The fields are arrays because a hymn can have several legitimate seasons, feast associations, categories, or canonical hours. A schedule may select `Automatic — Lauds`, `Automatic — Vespers`, or another canonical hour. LitCal always establishes the feast/saint/category/season match tier first; a selected canonical hour then narrows that tier when an hour-tagged candidate exists, otherwise the LitCal candidates are used unchanged. The ordinary automatic mode does not infer an office from the clock time.

The same tagging contract is present on `AudioAsset`, not only hymns, so future recordings, chants, prayers, and bell sequences can participate in the catalog without embedding feast rules in individual files. Imported recordings may supply `liturgicalTags` through the API or persistent asset manifest.

When LitCal is enabled, its celebrations are normalized into these tags. The highest-grade celebration becomes the day's primary celebration; automatic hymn selection prefers an exact feast, then an exact saint identity when available, then saint/category affinity, then the season, and finally the genuinely general pool. `General` is not treated as a category that outranks Ordinary Time. Selection defaults to random, supports sequential and fixed strategies, accepts a test seed, and keeps a small recent-exclusion window for unseeded random playback.

## Recordings

No third-party recording is currently bundled. This is intentional: a recording is only suitable for bundling after its creator, URL, license, attribution requirements, and redistribution permission have been verified. Use `virtual-carillon import --name "My Church Angelus" --file /path/to/angelus.wav` for local church recordings.

## Liturgical calendar source

LitCal is optional and uses the stable production API base `https://litcal.johnromanodorazio.com/api/v5`, with `GET /calendar/{year}?year_type=CIVIL` for the General Roman Calendar or the documented national-calendar route. The [OpenAPI specification](https://litcal.johnromanodorazio.com/api/v5/schemas/openapi.json) identifies the API as Apache 2.0 and documents the supported general/national calendars and response fields. Accessed 2026-08-23. Year responses are cached locally and stale data is used if the network is unavailable.
