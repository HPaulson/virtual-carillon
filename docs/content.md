# Content and recordings

Virtual Carillon keeps its bundled material and your own recordings separate.

## Bundled material

- **Bells, Westminster Chimes, Angelus signals, and Office signals** are generated by the engine. No sampled church-bell recordings are included.
- **Hymns** are stored as symbolic melody and timing data, then arranged and rendered for the virtual carillon when needed.
- Built-in hymn metadata identifies relevant seasons, feasts, categories, Offices, or canonical-hour preferences. The selector uses those tags when choosing hymns.

## Add a recording

For an advanced standalone engine, use the command line to copy a local recording into the persistent library:

```bash
node engine/dist/cli/index.js import \
  --name "Custom Angelus" \
  --file /path/to/custom-angelus.wav \
  --id custom-angelus
```

`--name` and `--file` are required. `--id` is optional; when you omit it, Virtual Carillon derives a stable ID from the source file name. IDs may contain letters, numbers, hyphens, and underscores after normalization.

The supported formats are WAV, FLAC, MP3, OGG, M4A, and AAC. The file is copied into the data directory, usually `.data/assets` for a local install or the `virtual-carillon-data` Docker volume for Compose. The original file is left untouched.

The command-line importer creates a general recording. For an imported hymn with liturgical metadata, use `POST /api/assets/import`; see the [API reference](api.md#import-a-recording).

Imported recordings appear in **All assets** in the Home Assistant media browser and can be selected in a Manual routine. Imported assets whose `type` is `hymn` also appear in the hymn browser and can participate in category, season, and automatic selection when their metadata supports it.

## Rights and local customs

Only import recordings, hymn performances, arrangements, or other material that you have permission to copy and use. Virtual Carillon does not grant permission to redistribute imported material.

Bell customs vary by place. The bundled Angelus and Office signals are usable starting points, not claims that one pattern is universal. A local recording can be a fitting way to preserve a local practice.

## Remove an imported recording

Use the API to remove an imported asset:

```bash
curl -X DELETE \
  -H 'Authorization: Bearer YOUR_TOKEN' \
  http://127.0.0.1:9876/api/assets/custom-angelus
```

This deletes the copied file from the engine’s data directory and removes it from the persistent library. It cannot remove bundled assets and does not delete the original source file you imported.
